Plan-to-apply evidence chain

Planned design, no code yet

Can a pipeline show that the plan ctfkit analyzed and a reviewer approved is the plan that was applied? Yes, with four checks. A random nonce in the plan is not one of them: sha256(tfplan) is already unique, and it is the thing to sign.

What binds approval to apply

1 / statementSigned statement S whose subject is sha256(tfplan).
2 / re-checkApply job decrypts that exact plan file, runs show -json and ctfkit scan again, compares findings and change set with S.
3 / one principalOnly the apply role can write. Trust pins the environment OIDC sub and the reusable workflow ref.
4 / single useDynamoDB ledger keyed on the digest of S. Each approval applies once.

A nonce as a root output would link state to a plan, but needs a customer config change and the ledger already stops replay. Optional, phase 2.

Terminal states never change. No pipeline role can delete. Exit 0 with an unchanged serial is noop for an empty change set and unknown otherwise. Rows export to object-locked storage for the evidence period.

Policy outside the scanned repo

Settings, exceptions, fail-on, permitted ?disable= controls, allowed ctfkit and Terraform versions, provider allowlist with lock hashes, per-environment backend, account, apply role, provider identities and reviewers. Code-owner reviewed, pinned by commit, enforced by the verifier.

The claim the evidence supports

Plan sha256:<X>, whose configuration matches commit <C>, analyzed by ctfkit <v> under policy <p> with findings <F> (derived again at apply), approved by <reviewer> in run <R>, was applied once by the apply role to <account/backend/workspace>; state moved from serial <n> to <m>.

Not covered: after_unknown, ephemeral and write-only values, non-literal provider identity, provider behaviour at apply, drift, module manifest authenticity, data read at plan time by PR code.

Applied as analyzed. Never "compliant".
